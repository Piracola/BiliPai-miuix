## 初学者解释

动效用来解释“什么改变了”：按钮被按下、页面进入、卡片变成详情、控制层消失。模糊、玻璃、阴影等效果用来帮助区分层级。它们都不是功能本身，设备能力不足或用户减少动态效果时，必须能安全降级。

## 规范要求

### 动效目的

| 目的 | 合理动效 | 禁止情况 |
|---|---|---|
| 操作反馈 | 按压、选中、开关变化 | 动画结束前不执行真实操作 |
| 空间连续 | 页面推入、预测返回、整卡过渡 | 来源不存在时强行播放假过渡 |
| 状态变化 | 加载转内容、展开/收起 | 无限闪烁或移动布局作为装饰 |
| 注意提醒 | 一次性轻提示 | 持续脉冲抢占媒体内容 |

- **必须**从 `AppMotionTokens` 或已有领域 motion policy 取得动画参数。
- **必须**保证取消动画后状态仍正确；动画不能成为提交、保存或导航的唯一触发器。
- **应该**让进入、退出、连续移动使用匹配的 easing 和方向。
- **禁止**在新业务代码中无理由直接写 `tween(...)`、`spring(...)`。
- **禁止**同时对同一元素施加多个竞争的缩放、位置和透明度动画。

### 双主题

Material 3 与 MIUIX 使用各自 chrome/motion token，可以“手感不同”，但完成状态、可取消性和返回结果必须一致。iOS 动效只属于历史代码清理范围，不形成运行时合同。

### 预测返回与共享元素

- 手势进行时，背景必须是实际来源页或同一来源的稳定快照语义，不允许整屏黑底或无关卡片。
- 取消预测返回后，详情页的缩放、透明度、模糊和播放器所有权必须完整恢复。
- 来源卡片离开视口或数据刷新时，应降级为普通页面返回，而不是错误拼接动画。
- 媒体播放器 surface 的生命周期优先于装饰过渡，不能因转场重复创建或泄漏。

### 模糊、玻璃和阴影

- **必须**先保证无模糊时的表面颜色、边界和文字对比可用。
- **必须**为 blur/shader 失败或低性能档位提供不透明/半透明普通表面降级。
- **应该**只在导航栏、控制层、悬浮层等确有层级意义的地方使用玻璃。
- **禁止**用大量装饰性光斑、渐变球体或模糊背景占据注意力。
- **禁止**在滚动列表的每一项叠加高成本实时模糊。

### 减少动态效果

用户或设备要求减少动效时：持续、弹性、粒子与大幅缩放应关闭或减弱；必要的状态反馈可以改成短淡入或立即切换。加载进度仍要可感知，不能完全静止且无文字说明。

## Compose 短示例

```kotlin
val spec = AppMotionTokens.standardSpec<Float>()
val alpha by animateFloatAsState(
    targetValue = if (visible) 1f else 0f,
    animationSpec = spec,
    label = "controlsAlpha"
)
```

## 代码映射

- 公共参数：`AppMotionTokens.kt`、`AppMotionEasing`
- 设备动效档位：`DeviceUiProfile`、`MotionTier`
- 可恢复效果：`RecoverableVisualEffects`
- 预测返回与卡片过渡：`PredictiveBackBackgroundPolicy`、视频卡片 morph 相关策略
- 玻璃效果：设计系统 blur 与 home liquid 相关策略

## 当前差距

旧业务组件仍存在局部弹簧、脉冲和按压比例；个别页面同时实现自己的玻璃卡。共享元素与播放器场景复杂，当前人工检查覆盖多于自动检查。

## 验收方法

1. 正常完成、手势取消、快速重复和来源刷新四种情况下检查返回。
2. 关闭或降级模糊后，导航、文字、边界和点击仍完整可用。
3. 低动效模式下不出现持续脉冲、粒子或大幅缩放。
4. 连续进入/退出视频详情 8 次，观察控制层、播放状态和内存行为；只记录文字结果，不要求截图。
