## 初学者解释

本文件只记录“设计规范本身”发生的变化，不记录每一次 UI 代码提交。阅读某个版本条目时，先看 What 知道改了什么，再看 Why 和 How 理解原因与使用方式。

## 规范要求

- 每次改变规则、组件目标入口、页面母版或验收矩阵都必须新增条目。
- 只修正错字或失效链接使用 Patch；新增兼容规则使用 Minor；改变共同合同使用 Major。
- 草案评审通过前保持 `1.0.0-draft`，不能提前宣称正式稳定。

## 1.2.0-draft - 2026-08-10

### What：设置页优化计划评审修订

- 明确“目标架构”是收敛方向而非现状：禁止为满足架构图新建全局 SettingsUiState 或统一 MVI 层。
- UI-12 P1 新增“设置页之外 `AppListItemStyle.AUTO` 行为不变”回归测试；P2 新增 MIUIX 居中标题 capability spike 与 840dp 双栏详情面板顶部栏契约；P3 新增稳定行/组 key 搜索定位（条件项/HOME/双栏三场景）与 HomeSettings 联动；P4 显式延期。
- 新增决策记录 D1-D4：执行范围、恢复主题推荐语义（仅清视觉覆盖）、说明卡降级为小字/问号提示、顶部栏目标。
- 验收矩阵补充 TalkBack 读屏、Material 3 深色 `surfaceContainer` 层级与 MIUIX SNAPSHOT 依赖解析前置检查。
- 清理设置页档案中过时的“文件正在用户修改”陈述（P008/P016/P017/P020/P023），同步更新差距台账 UI-GAP-008/009。

### Why：变更原因

首版计划评审发现三处真实风险：搜索定位依赖硬编码 LazyColumn 索引、`AppearanceSettingsScreen` 被首页设置页共享复用、MIUIX 居中标题缺少现成组件能力；同时文档残留与当前工作区不符的时效性陈述。

### How：使用方式

实施从 UI-12 P1 开始，先写纯策略与回归测试再接入 UI；P3 前先完成稳定 key 搜索定位；双栏面板契约在 P2 完成；P4 另行开任务。

## 1.1.0-draft - 2026-08-10

### What：双主题设置页视觉合同

- 将现行规范从历史“三风格”事实统一到 MIUIX / Material 3 两种运行时主题；iOS 只保留迁移说明。
- 根据 Google Play Material 3 与小米系统设置参考，定义两主题各自的设置页分组、标题、图标、行和 trailing 语法。
- 明确共同信息架构不等于像素一致，禁止在 feature 层复制两份 Screen。
- 新增[设置页 UI 优化计划](12_SETTINGS_UI_OPTIMIZATION_PLAN.md)，按视觉策略、共享 Scaffold、外观页试点、分批迁移和验收推进。
- 新增设置页视觉策略与外观页信息架构差距任务卡。

### Why：变更原因

运行时代码已经收敛为双主题，但文档仍残留 iOS/三风格合同；共享设置 Scaffold 又统一强制扁平分组和填充图标，使两主题没有形成各自完整的官方设置页语法。

### How：使用方式

页面继续只调用 `AppPreference*`；主题差异由 visual policy、Token 和 Renderer 解析。实现从 UI-12 的 P1 开始，不在本次规范修订中改变生产 UI。

## 1.0.0-draft - 2026-08-02

### What：新增内容

- 建立基础、主题、组件、页面母版、61 个导航 Key 档案、验收和维护文档。
- 确认 Miuix 为主设计与完整验收基准，保留 iOS、Material 3 兼容模式。
- 新增目标规范与当前实现差距台账，以及文档结构自动检查合同。

### Why：变更原因

当时项目仍按历史三风格设计系统和大量业务页面建立首版文档，但缺少适合初学者阅读、同时可被工程检查的统一规则。

### How：使用方式

从[总目录](README.md)进入；开发页面时依次查页面档案、母版、组件和 Token；发现实现不符时在[差距台账](10_GAP_LEDGER.md)登记。

### P005 搜索试点：共享内容状态

**What**：新增 `AppErrorState`、`AppEmptyState`，并在综合搜索中区分首次错误、分页错误、热榜/发现局部错误与空结果。

**Why**：已有结果不应因下一页失败而消失；整页失败和局部失败需要不同的恢复动作与播报语义。

**How**：使用 `AppContentStatePresentation.PAGE/INLINE`；通过 `SearchContentStatePolicy` 决定 body/footer；按 `SearchViewModel` 的错误字段维护状态；其他页面迁移前继续保留旧实现。
